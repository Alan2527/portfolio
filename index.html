Motor de Regresión Visual

Herramienta propia construida desde cero con Selenium y Pillow que detecta regresiones visuales entre dos versiones del mismo sitio. En vez de comparar píxel contra píxel — que genera falsos positivos con cualquier diferencia de renderizado — recorre el DOM y compara elemento por elemento su geometría y sus estilos computados.

Clasifica cada diferencia encontrada en nueve categorías (tamaño, posición, tipografía, color, visibilidad, apilamiento, interactividad, recorte y contenido) y trabaja con tolerancia 0px, de modo que ningún desplazamiento pase inadvertido. El informe resultante es interactivo: al hacer clic en una diferencia de la lista, se resalta el elemento exacto sobre la captura, y muestra lado a lado la versión base contra la candidata.

Suite E2E — SauceDemo

Suite de regresión funcional end-to-end con Selenium y Pytest que cubre 17 casos sobre autenticación, catálogo, carrito y flujo de compra. Está organizada por área funcional en lugar de un único directorio de tests, con asignación automática de marcadores según la carpeta, lo que permite ejecutar una suite puntual desde el pipeline sin tocar código.

Cada paso de cada test adjunta su propia captura de pantalla al reporte, incluso cuando el paso falla a mitad de camino, de modo que el diagnóstico de una falla no depende de reproducirla localmente. Incluye además una auditoría de defectos conocidos con xfail estricto: los bugs plantados quedan documentados en el reporte sin romper el pipeline, y si alguno se corrige, la suite avisa.

Suite de API — Restful-Booker

Suite de 13 casos sobre una API REST pública de reservas, cubriendo salud y autenticación, creación y lectura, y actualización y borrado. El plumbing HTTP está encapsulado en un cliente propio, de modo que los tests expresan qué se valida y no cómo se arma cada request.

Las respuestas se validan contra esquemas JSON — estructura, tipos y formatos de fecha — y no solo contra valores puntuales, lo que detecta cambios de contrato que un assert sobre un campo dejaría pasar. Cada reserva de prueba se elimina al terminar aunque el test falle, y los comportamientos no estándar de la API (el DELETE responde 201, las credenciales inválidas responden 200) quedan fijados con asserts documentados: si algún día se corrigen, la suite avisa.
